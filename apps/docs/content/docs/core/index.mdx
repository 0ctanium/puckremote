`@puck-remote/core` loads and verifies theme versions, runs blocks in the sandbox, resolves their
data, renders pages with Puck, serves the editor and its API, and enforces auth, origins and CSP.
It has no framework imports: it works with standard `Request` and `Response`.

```npm
npm install @puck-remote/core
```

Peer dependencies: `react` and `react-dom` 19, `@puckeditor/core` ~0.23. Node 24+ (isolated-vm).

## `createCore(config)`

```ts
import { createCore } from '@puck-remote/core';
import config from './puck-remote.config';

const core = createCore(config);
```

Returns one **process-wide runtime per `config.id`** (memoized on `globalThis`), so every route of
your app shares the same artifact loader, worker pool and cache. The first theme version is loaded
lazily on first use.

## Errors

| Error | When | Answer |
|---|---|---|
| `ConfigError` | Invalid config, or a production guard failed | Fix the config |
| `WrongSurfaceError` | The editor was requested on a non-editor origin | 404 |
| `AccessDeniedError` | `status` 401 (no principal) or 403 (not allowed) | 401/403, or 404 to hide the editor |
