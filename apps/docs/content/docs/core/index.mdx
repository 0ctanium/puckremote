`@puck-remote/core` loads and verifies theme artifacts (code and pages), runs blocks in the
sandbox, resolves their data, renders pages with Puck, reads and writes pages inside artifacts,
and prepares what the editor needs. It has no framework imports and no authority of its own
([D-0187](/docs/internal/decisions#D-0187)): auth, publishing workflows and caching belong to your app.

```npm
npm install @puck-remote/core
```

Peer dependencies: `react` and `react-dom` 19, `@puckeditor/core` ~0.23. Node 24+ (isolated-vm).

## `createCore(config)`

```ts
import { createCore } from '@puck-remote/core';
import config from './puck-remote.config';

const core = createCore(config);
```

Returns one **process-wide runtime per `config.id`** (memoized on `globalThis`), so every route of
your app shares the same artifact loader and worker pool. The first artifact is loaded lazily on
first use.

## Errors

| Error | When | Answer |
|---|---|---|
| `ConfigError` | Invalid config, or `editorPayload` without `origins` | Fix the config |
| `PageError` | `writePage` with invalid data, slug or base, or a page over 2 MB | 400 |
| `UnknownBlockError` | `resolveBlockData` for a block the artifact doesn't have | 404 |
