`@puck-remote/core` loads and verifies theme artifacts (code and templates), runs blocks in the
sandbox, resolves their data, renders templates with Puck, reads and writes templates inside
artifacts, and prepares what the editor needs. It has no framework imports and no authority of its
own ([D-0187](/docs/internal/decisions#D-0187)): routing, auth, publishing workflows and caching
belong to your app.

## Templates

Like a Shopify theme, an artifact carries **templates**: named Puck documents
(`templates/<name>.json`) with any root props. The core never maps URLs to templates: your app
decides which template a route renders and which **params** it gets (for example
`/products/[handle]` → template `product` with `{ handle }`), and builds the page metadata from
the template's root props ([D-0371](/docs/internal/decisions#D-0371),
[D-0370](/docs/internal/decisions#D-0370)).

```npm
npm install @puck-remote/core
```

Peer dependencies: `react` and `react-dom` 19, `@puckeditor/core` ~0.23. Node 24+ (isolated-vm).

## `createCore(config)`

```ts
import { createCore } from '@puck-remote/core';
import config from './puck-remote.config';

const core = createCore(config);
```

Returns one **process-wide runtime per `config.id`** (memoized on `globalThis`), so every route of
your app shares the same artifact loader and worker pool. The first artifact is loaded lazily on
first use.

## Errors

| Error | When | Answer |
|---|---|---|
| `ConfigError` | Invalid config (including `root.fields`), or `editorPayload` without `origins` | Fix the config |
| `TemplateError` | `writeTemplate` with invalid data, name or base, a template over 2 MB, or invalid params | 400 |
| `UnknownBlockError` | `resolveBlockData` for a block the artifact doesn't have | 404 |
