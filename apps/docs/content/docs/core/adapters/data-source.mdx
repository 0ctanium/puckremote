---
title: Data source
description: Answer the find, findByID and global queries of blocks from your CMS, database or API.
---

A data source declares **which collections and fields themes may reach**, and implements storage.
The engine enforces the declared policy before and after calling you.

```ts title="src/cms.ts"
import { defineCollection, defineDataSource, defineGlobal } from '@puck-remote/sdk/host';

export const myCms = () =>
  defineDataSource({
    name: 'my-cms',
    collections: {
      posts: defineCollection<Post>()({
        fields: {
          title: { type: 'text' },                         // all operators, sortable
          slug: { type: 'text', filter: ['equals', 'in'] },
          excerpt: { type: 'text', filter: false, sort: false },
          author: { type: 'relation', to: 'authors' },     // populated docs use the authors policy
        },
        limits: { default: 10, max: 12, maxDepth: 1 },
        find: async (query, ctx) => ({ docs, totalDocs }),
        findByID: async (id, { select, depth }, ctx) => doc, // optional
      }),
    },
    globals: {
      site: defineGlobal<Site>()({ fields: { tagline: { type: 'text' } }, get: async (ctx) => site }),
    },
  });
```

## Who is asking: `requireRequest`

By default a source never sees the request: every query is anonymous. A source that answers per
visitor (a CMS with access control, members-only content, drafts for signed-in editors) declares
`requireRequest: true`. Every query then receives `ctx.request`:

- on public pages and previews, the visitor's request (rebuilt from the page's headers by the
  Next.js bindings: the headers and the origin, not the path);
- in the editor, the request your `resolveData` handler forwards (`core.resolveBlockData(…, { request })`),
  or none;
- `null` when there is no request: treat it as anonymous.

The source decides who the request belongs to (a session cookie, a token…). Theme code never sees
the request ([D-0595](/docs/internal/decisions#D-0595)).

```ts
defineDataSource({
  name: 'my-cms',
  requireRequest: true,
  collections: {
    posts: defineCollection<Post, true>()({          // `true`: ctx.request is typed
      fields: { title: { type: 'text' } },
      find: async (query, ctx) => {
        const user = ctx.request ? await userOf(ctx.request) : null; // null: anonymous
        return findVisibleTo(user, query);
      },
    }),
  },
  globals: {},
});
```

A collection or global that reads `ctx.request` in a source without `requireRequest: true` is a
type error.

<Callout type="warn">
Results that vary per visitor must not be cached for everyone. With `requireRequest: true`, every
template running a query of this source is **uncacheable**: `cacheable: false`, and the Next.js
proxy answers `cache-control: no-store` ([D-0596](/docs/internal/decisions#D-0596)). Templates
using only HTTP adapters or no data stay cacheable.
</Callout>

You don't need to filter fields in your output: the engine projects results to the declared
fields, including populated relations. The core does not cache results: cache inside your source
if you need to ([D-0187](/docs/internal/decisions#D-0187)).

## `@puck-remote/source-mock`

An in-memory example (posts, authors, a `site` global) loaded from JSON. Useful for demos and tests.

```ts
import { mockCms } from '@puck-remote/source-mock';

source: mockCms({
  dataFile: path.join(process.cwd(), 'data/cms.json'),
  canReadDrafts: (request) => !!sessionOf(request), // drafts for signed-in admins only
}),
```
