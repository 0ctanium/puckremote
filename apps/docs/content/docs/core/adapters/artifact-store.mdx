title: Artifact store

The artifact store keeps the site's [themes](/docs/concepts/themes): the theme list, and each
theme's **current files** (`manifest.json`, the bundles, `assets/**`, `templates/**`), like a Shopify
store keeps its themes' files ([D-0506](/docs/internal/decisions#D-0506)). "Artifact" names a
theme's built files; there is no history of older versions.

## `@puck-remote/artifacts-fs`

The default store, on the local filesystem. Suits a single server.

```npm
npm install @puck-remote/artifacts-fs
```

```ts
import { fsArtifactStore } from '@puck-remote/artifacts-fs';

artifacts: fsArtifactStore({ dir: path.join(process.cwd(), 'artifacts') }),
```

<TypeTable type={{ dir: { description: "Directory holding themes.json and one folder per theme.", type: 'string', required: true } }} />

```files
artifacts
├── themes.json
└── themes
    ├── 0f3a9c21b7d4
    │   ├── manifest.json
    │   ├── bundle.js
    │   ├── bundle.browser.js
    │   ├── assets
    │   └── templates
    └── a3f9c1e2b4d6
```

- One folder per theme, holding only its current files ([D-0513](/docs/internal/decisions#D-0513)).
  A push writes the files that changed **in place**. Each file is written to a temporary name and
  renamed, so a reader never sees a half-written file. During a push a reader may see some new and
  some old files, as with a Shopify theme ([D-0509](/docs/internal/decisions#D-0509)); the theme's
  `hash` only changes once every file is written.
- `copyFiles` (duplicating a theme) hard-links the files: large assets are not copied, and since
  writes replace files by rename, changing one theme never changes the other.
- The theme list is `themes.json` (`{"themes": [...]}`), replaced atomically (temp file + rename).
  Its version is the sha256 of the file. Writes take a lock file, `.themes.lock`, so the version
  check is safe across processes; a lock older than 10 seconds is from a crashed writer and is taken
  over.
- `watch` reports changes of `themes.json` from a directory watcher (it creates the directory if
  needed), so the host switches within ~100 ms when the main theme changes.
- Reads resolve symlinks and refuse anything outside the theme's folder.

## Themes

A site has **themes**, like a Shopify store ([D-0444](/docs/internal/decisions#D-0444)): named sets of
files with a role and a `hash` (the sha256 of their `manifest.json`, their version). See
[Themes](/docs/concepts/themes). The core owns every rule: ids, names, roles, one main theme,
expiry, which files a theme may hold and their sha256 ([D-0514](/docs/internal/decisions#D-0514)).
The store keeps the list, replaced atomically, and moves bytes.

## Writing your own

For serverless or several instances, use a shared store (S3, a database…), such as
[`payloadArtifactStore`](/docs/core/adapters/payload#artifact-store-payloadartifactstore) when you use Payload.

```ts
import { ThemeConflictError, type ArtifactStore, type Theme } from '@puck-remote/sdk/host';
```

/>

`writeThemes` is a compare-and-swap: make the version check and the write atomic together (a
conditional write, a transaction, or a lock). On mismatch, throw `ThemeConflictError` (its `code`
is `'THEME_CONFLICT'`); the core reads again and retries.

The store only moves bytes. The core writes a theme's changed files first, `manifest.json` last,
then removals, and only then updates the theme's `hash` in the list
([D-0514](/docs/internal/decisions#D-0514)). Theme ids are 12 lowercase hex characters; paths are
relative POSIX paths already validated by the core; still refuse escapes. Check your store with
[`artifactStoreContract`](/docs/core/adapters/testing).
