## `@puck-remote/pages-fs`

An example store with one JSON file per page.

```npm
npm install @puck-remote/pages-fs
```

```ts
import { fsPageStore } from '@puck-remote/pages-fs';

pages: fsPageStore({ dir: path.join(process.cwd(), 'data/pages') }),
```

<TypeTable type={{ dir: { description: "Directory of page files. Nested slugs map '/' to '__' (blog/post-1 → blog__post-1.json).", type: 'string', required: true } }} />

Writes are atomic (temp file + rename).

## Writing your own

<TypeTable
  type={{
    get: { description: "Page JSON for a slug, or null.", type: '(slug: string) => Promise<unknown | null>', required: true },
    put: { description: "Save a page.", type: '(slug: string, data: unknown) => Promise<void>', required: true },
    list: { description: "All slugs.", type: '() => Promise<string[]>', required: true },
  }}
/>

Slugs are validated by the host before they reach you: lowercase `a-z0-9-` segments, up to 5
levels (`home`, `blog/post-1`). The host validates pages and removes editor-only data before
`put`. Check your store with [`pageStoreContract`](/docs/core/adapters/testing).

  A publishing workflow (drafts, history, preview links) will be added to this contract in a
