---

| Import | Content | Loads the sandbox? |
|---|---|---|
| `@puck-remote/core` | `createCore`, renderers, errors, types | yes (lazily) |
| `@puck-remote/core/config` | `defineConfig`, `resolveOrigins` | no |
| `@puck-remote/core/edge` | Security headers, request origin, template cacheability | no |
| `@puck-remote/core/react` | `PuckRemoteTemplate` (server component) | no |
| `@puck-remote/core/testing` | The artifact store contract test suite (vitest) | no |

Use `/config` in your config file and `/edge` in middleware or proxies: they never import
isolated-vm. The editor lives in its own package, `@puck-remote/editor`
(`/protocol`, `/frame`, `/bridge`; see [The editor](/docs/concepts/editor)).

## `@puck-remote/core`

`createCore`, `defineConfig`, `resolveConfig`, `DEFAULT_ROUTES`, `ConfigError`,
`TemplateError`, `MAX_TEMPLATE_BYTES`, `UnknownBlockError`, `inProcessRenderer`, `workerPoolRenderer`,
`bubblewrap`, `workerLaunchOptions`, and the types (`EditorPayload`, `EditorOrigins`, `TemplateData`,
`TemplateOptions`, `PreparedTemplate`, `Manifest`…). Mapping URLs to template names is your
app's job: the core has no slug helper ([D-0391](/docs/internal/decisions#D-0391)).

## `@puck-remote/core/react`

- `<PuckRemoteTemplate template={template} />`: renders a `PreparedTemplate` (server component).
  Page metadata is yours to build, typically from `template.data.root.props`
  ([D-0370](/docs/internal/decisions#D-0370)).
