---
title: HTTP API
description: The theme route served by the core, and the editor RPC route of the Next bindings.
---

The core answers one route, `routes.theme` (default `/theme`). Everything else (admin pages, RPCs,
publishing) is your app's, so it uses your app's own session ([D-0187](/docs/internal/decisions#D-0187)).

## Theme route

| Method & path | Response |
|---|---|
| `GET\|HEAD /theme/<id>/assets/**` | The file if listed in that artifact's manifest and hash-valid; `immutable`; otherwise `404` |
| `GET\|HEAD /theme/<id>/bundle.browser.js` | The theme's browser bundle (ESM), same checks |

`bundle.js`, `manifest.json` and `pages/**` are never served (`404`). Other methods get `405`.
With `origins` configured, served files carry `access-control-allow-origin: <editor origin>` and
`cross-origin-resource-policy: cross-origin`, so the editor can import the bundle and show assets
in its canvas.

## Editor RPC route (Next bindings)

`remote.createEditorRpcRoute(handlers)` builds a `POST` handler for the calls your admin page
makes: the RPCs it relays from the editor and its own actions.

| Request | Response |
|---|---|
| `POST { method, params }` | `200 { value }`: what the handler returned |
| `Origin` missing or not an admin origin, or request not on an admin origin | `404` |
| Body over 1 MB | `413` |
| Invalid JSON | `400` |
| `method` not in `handlers` | `404` |

Handlers receive `(params, request)` and must check your admin session on `request`. Responses
carry `cache-control: private, no-store`.

The calls the editor may make are limited twice: by the `rpc` map you give `<PuckEditorFrame>`
(the only methods the iframe can reach), and by this route's handlers. See
[Editor protocol](/docs/internal/architecture/editor-protocol).
