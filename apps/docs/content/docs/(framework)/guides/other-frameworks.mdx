---
title: Other frameworks
description: Use the framework-agnostic core directly from any server that speaks Request and Response.
---

`@puck-remote/next` is a thin layer. Any framework can bind to `createCore(config)` from
`@puck-remote/core` instead.

```npm
npm install @puck-remote/core @puck-remote/editor
```

| You need | Use |
|---|---|
| Public page | `core.preparePage(slug, query, { locale })` then render `<PuckRemotePage page />` (RSC-safe) |
| Page metadata | `pageMetadata(page)` |
| Admin page | `core.editorPayload(slug)` then render `<PuckEditorFrame payload … />` (client) |
| Editor data RPC | `core.resolveBlockData(slug, block, props)` in your own authenticated route |
| Saving pages | `core.writePage(slug, data, { base })`, then `config.artifacts.writePointer(id)` to go live |
| Theme files | `core.handleTheme(request)` |
| Middleware | `@puck-remote/core/edge`: `securityHeaders`, `cspNonce`, `requestOrigin`, `pageCacheability` |

```ts title="server.ts"
import { createCore } from '@puck-remote/core';
import config from './puck-remote.config';

const core = createCore(config);

export async function handle(request: Request): Promise<Response> {
  const { pathname } = new URL(request.url);
  if (pathname.startsWith('/cdn/')) return core.handleTheme(request);
  // pages: core.preparePage(...) / core.editorPayload(...) inside your renderer
  return new Response('Not found', { status: 404 });
}
```

Keep `@puck-remote/core` external to your bundler: it forks render workers from its own files.
Rules to respect in your binding:

- `preparePage` returns `null` for unknown pages: answer 404.
- Never serve public pages on an admin origin, nor admin pages elsewhere
  (`requestOrigin(request)` against `config.origins.host`).
- Accept RPC and publish calls only from admin origins, with your session.
- Behind a proxy, forward `X-Forwarded-Host` and `X-Forwarded-Proto`.

See the [Core reference](/docs/core) and how the Next binding does it in
[Next.js API](/docs/next-js/api).
