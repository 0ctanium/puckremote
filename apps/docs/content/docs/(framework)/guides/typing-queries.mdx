---
title: Typing host queries
description: Get compile-time checking of collections, fields, sort keys and globals in theme code.
---

Host queries are typed from the host's **data source type**. Register it once in the theme. It is
type-only, so nothing from the source package enters the bundle ([D-0037](/docs/internal/decisions#D-0037)):

```ts title="puck-remote-env.d.ts"
import type { MockCms } from '@puck-remote/source-mock'

declare module '@puck-remote/sdk' {
  interface Register { source: MockCms }
}
```

Then `find('posts', { select: ['title', 'slug'] })` returns
`QuerySpec<FindResult<Pick<Post, 'id' | 'title' | 'slug'>>>`. Unknown collections, fields, sort
keys and globals are compile errors (`examples/theme/type-tests.ts`).

Without registration, use the explicit form:

```ts
import { source } from '@puck-remote/sdk'
const q = source<MockCms>().find('posts', { limit: 3 })
```

`find<MockCms>('posts')` is not offered: TypeScript has no partial generic inference, so it could
not infer the collection name once one generic is given explicitly.

## How the types flow

`defineCollection<Post>()({...})` stores a phantom document type on the collection definition. The
helpers `CollectionName<S>`, `DocOf<S, K>`, `GlobalName<S>` and `GlobalDocOf<S, K>` in
`@puck-remote/sdk/host` extract it, and the query builders use them.

Types only help honest themes; the host still enforces the policy at runtime.
