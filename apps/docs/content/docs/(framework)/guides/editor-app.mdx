---
title: Customizing the editor
description: Compose your admin page around Puck (fields, header, publishing) and customize the editor frame (canvas, drawer, outline).
---

The editor has two halves ([D-0325](/docs/internal/decisions#D-0325)):

- **`<PuckEditorFrame>`** (`@puck-remote/editor/frame`) on your **admin page**. It's a real
  `<Puck>`: it holds the page data, the history and the fields, so your header, Publish button and
  plugins live there, next to your session.
- **`<PuckRemoteEditor>`** (`@puck-remote/editor/react`) on your **editor page** (another site).
  It shows the canvas, the drawer and the outline with the theme's components, and proposes
  actions to the admin page.

```npm
npm install @puck-remote/editor @puckeditor/core
```

## The admin page

Compose the layout yourself: `<PuckEditorFrame>` renders Puck's context, so its children can use
Puck's components and hooks. Place `<PuckEditorFrame.Canvas />` where the editor frame goes.

```tsx title="app/admin/editor/ClientEditor.tsx"
'use client';
import { createUsePuck, Puck } from '@puckeditor/core';
import { PuckEditorFrame, stripResolved, usePuckEditorFrame } from '@puck-remote/editor/frame';
import { publish, resolveData } from './actions'; // your server actions (check the session)

const usePuck = createUsePuck();

function Header({ slug }: { slug: string }) {
  const history = usePuck((s) => s.history);
  const data = usePuck((s) => s.appState.data);
  const { setLeftSideBarVisible } = usePuckEditorFrame();
  // "Unpublished changes": compare stripResolved(data) with the last published state.
  return (
    <header>
      <button disabled={!history.hasPast} onClick={() => history.back()}>Undo</button>
      <button disabled={!history.hasFuture} onClick={() => history.forward()}>Redo</button>
      <button onClick={() => publish({ slug, data })}>Publish</button>
    </header>
  );
}

export function ClientEditor({ payload, editorUrl }) {
  return (
    <PuckEditorFrame
      payload={payload}
      editorUrl={editorUrl}
      resolveData={async (block, props) => (await resolveData({ slug: payload.slug, block, props })).data}
    >
      <Header slug={payload.slug} />
      <div style={{ display: 'grid', gridTemplateColumns: '1fr 320px', height: 'calc(100vh - 48px)' }}>
        <PuckEditorFrame.Canvas />
        <Puck.Fields />
      </div>
    </PuckEditorFrame>
  );
}
```

Without children, `<PuckEditorFrame>` renders the canvas and the fields side by side.

Inside it, `usePuckEditorFrame()` gives `{ payload, frameReady, setLeftSideBarVisible(visible) }`.
Puck's own `createUsePuck()` gives the data, the selection and the history, because this side's
Puck is the one that holds them. `stripResolved(data)` returns the page as it will be saved: the
data blocks fetched (`__data`) is removed. Compare it with the last published version to show
unsaved changes.

## The editor page (Next.js)

The proxy serves `routes.editor` (default `/editor`) at the root of `origins.editor` and answers
404 for it on every other origin.

```tsx title="app/editor/page.tsx"
import { remote } from '@/puck-remote';
import { EditorPage } from './EditorPage';

export const dynamic = 'force-dynamic';

export default async function Editor() {
  // notFound() outside origins.editor
  const { allowedParents } = await remote.loadEditorPage();
  return <div style={{ height: '100vh' }}><EditorPage allowedParents={allowedParents} /></div>;
}
```

```tsx title="app/editor/EditorPage.tsx"
'use client';
import '@puckeditor/core/no-external.css';
import { PuckRemoteEditor } from '@puck-remote/editor/react';

export function EditorPage({ allowedParents }: { allowedParents: string[] }) {
  return <PuckRemoteEditor allowedParents={allowedParents} />;
}
```

Import Puck's stylesheet yourself (`no-external.css` loads no third-party font). It shows Puck's
own UI ([D-0326](/docs/internal/decisions#D-0326)): the Blocks/Outline sidebar and the canvas with
its toolbar. Puck's header and fields panel are removed, since they belong to the admin page.

Puck's `config`, `data` and `permissions` come from the admin page through the protocol; they
aren't props. Keep `overrides` and `plugins` stable (module constants or `useMemo`): Puck remounts
overrides whose identity changes. Undo/redo shortcuts pressed in the frame go to the admin page's
history.

## Calling your admin page from the frame: `useEditor()`

Inside the editor frame (overrides, plugins), `useEditor()` gives `{ rpc, payload, options }`
([D-0231](/docs/internal/decisions#D-0231)):

```tsx
function MediaBrowser() {
  const { rpc } = useEditor();
  const [items, setItems] = useState([]);
  useEffect(() => { rpc('media.list', { q: '' }).then(setItems); }, [rpc]);
  /* … */
}
```

`rpc(method, params)` reaches only the methods your admin page lists in
`<PuckEditorFrame rpc={{ … }}>`. Anything else is refused, and requests are size- and
rate-limited ([editor protocol](/docs/internal/architecture/editor-protocol)). The admin page runs
them with its own session. Theme code in the frame can call them too, so list only harmless
methods.

### Typed calls

Give `useEditor` the type of your admin page's `rpc` map, and `rpc` checks method names, params
and results ([D-0317](/docs/internal/decisions#D-0317)). Export the map from its own module on the
admin side, and import only its **type** on the editor side: no admin code reaches the editor
bundle.

```ts title="app/admin/editor/rpc.ts"
import type { RpcHandlers } from '@puck-remote/editor/frame';
import { currentUser } from './actions';

export const rpc = { currentUser } satisfies RpcHandlers;
export type AdminRpc = typeof rpc;
```

```tsx title="app/editor/EditorPage.tsx"
import type { AdminRpc } from '@/app/admin/editor/rpc';

function Badge() {
  const { rpc } = useEditor<AdminRpc>();
  useEffect(() => {
    rpc('currentUser').then(setUser); // Promise<string>
    // rpc('nope') is a type error
  }, [rpc]);
  /* … */
}
```

- A handler takes one `params` value; a handler without parameters is called as `rpc('name')`.
- The result type is the handler's return type. Results cross `postMessage`, so return JSON
  (plain objects, arrays, strings, numbers, booleans, `null`); anything else is refused at
  runtime.
- The type is your assertion: it isn't checked at runtime. Without a type argument, `rpc` stays
  loosely typed.

## How the theme gets React

`bundle.browser.js` doesn't bundle React or the SDK: it reads them from
`globalThis.__puckRemoteModules`, which `<PuckRemoteEditor>` fills with your app's copies before
loading the theme ([D-0229](/docs/internal/decisions#D-0229)). The theme and Puck therefore share
one React, and nothing has to be configured. The admin page never loads the theme.

## Production

Use **another site** for `origins.editor` (a second domain, even when it points at the same
deployment), so the editor never receives your app's cookies. The editor origin serves your app's
JavaScript chunks. Any server action or route reachable there runs without the admin session, so
check auth in each of them, as you already must ([D-0234](/docs/internal/decisions#D-0234)).
