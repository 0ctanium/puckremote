---
title: Serving the editor
description: The editor ships built in @puck-remote/editor; serve it from your Next.js app, your own server, or the bin.
---

`@puck-remote/editor` contains the **built editor**: a static page with Puck, the puck-remote
bridge and an import map ([D-0221](/docs/internal/decisions#D-0221)). Nothing to build; you only serve it,
on its own origin (`origins.editor`), with headers that let only your admin origins embed it.

```npm
npm install @puck-remote/editor
```

The page receives the admin origins at runtime, as a JSON data block the server injects
([D-0222](/docs/internal/decisions#D-0222)), so one build works for every deployment.

## From your Next.js app (one app, all origins)

Point the editor's hostname at the same deployment and add one route:

```ts title="app/editor/[[...path]]/route.ts"
import { remote } from '@/puck-remote';

export const { GET, HEAD } = remote.editor;
```

`createProxy` rewrites **every** request on `origins.editor` to this route (`/app.js` becomes
`/editor/app.js`), so none of your app's pages, API or theme routes are reachable on the editor
origin; on every other origin, `/editor/**` answers 404 ([D-0225](/docs/internal/decisions#D-0225)). The
prefix is `routes.editor` (default `/editor`). `withPuckRemote` keeps `@puck-remote/editor`
external to the server bundle, because the handler reads the built editor from its package files.

## From your own server

```ts title="server.ts"
import { createEditorHandler } from '@puck-remote/editor/server';

const handle = createEditorHandler({ adminOrigins: ['https://admin.example.com'] });
// (request: Request) => Promise<Response>, for any server that speaks fetch Requests
```

It answers `GET`/`HEAD` for `/`, `/index.html`, `/app.js`, `/app.css` and `/vendor/*.js`; anything
else is 404, other methods 405 ([D-0223](/docs/internal/decisions#D-0223)). Node only: it reads
`dist/static` from the package once and keeps it in memory.

## With the bin

```bash
npx puck-remote-editor --admin-origins https://admin.example.com --port 3300 --host 0.0.0.0
```

## Headers

Every response carries the editor's [security headers](/docs/security-headers#editor) and never sets
a cookie. Hashed asset URLs are cached as immutable; the page itself is `no-store`.

## Configure your app

```ts title="puck-remote.config.ts"
origins: { admin: ['https://admin.example.com'], editor: 'https://editor.example.net' },
```

and point `<PuckEditorFrame editorUrl="https://editor.example.net/" editorOrigin="https://editor.example.net" … />`
at it. Use **another site** for the editor in production (a second domain, even when it points at
the same deployment), so it can never receive your app's cookies.
