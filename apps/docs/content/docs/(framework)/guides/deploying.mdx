---
title: Deploying safely
description: The checklist for a production deployment.
---

1. **Three origins.** The public site and your admin pages on two hostnames of your app (e.g.
   `www.example.com`, `admin.example.com`), and the editor on **another site** (e.g.
   `editor.example.net`) pointing at the same app, which serves its editor page there. Set
   `origins: { host, editor }`; the config is refused if the editor origin is a host origin
   ([D-0238](/docs/internal/decisions#D-0238)). See [Customizing the editor](/docs/guides/editor-app).
2. **Host-only admin cookies.** Never `Domain=.example.com`: theme scripts run on the public site.
   The editor needs no cookies at all.
3. **Authenticate everything that acts.** Your admin pages, the server actions or routes behind
   the frame's `rpc` map, and your publish action check your own session: the core has no auth.
   Server actions are reachable from the editor origin too, where theme code runs
   ([D-0187](/docs/internal/decisions#D-0187)).
4. **Forward the addressed host.** Behind your own reverse proxy, forward
   `X-Forwarded-Host`/`X-Forwarded-Proto` (or preserve `Host`).
5. **Rendering.** The default `workerPoolRenderer()` runs theme code in permission-restricted
   worker processes (`size` defaults to min(4, CPUs); `maxCallsPerWorker` recycles them). On Linux,
   `workerPoolRenderer({ wrap: bubblewrap() })` adds namespaces (no network, read-only root):
   experimental, needs unprivileged user namespaces (Ubuntu 24.04: disable
   `kernel.apparmor_restrict_unprivileged_userns`). Keep `@puck-remote/core` external to your
   bundler.
6. **CSP.** Admin pages get an enforced CSP that frames only the editor. The site starts
   **report-only**: list third-party origins your themes need in `security.scriptOrigins` /
   `styleOrigins`, watch reports, then set `security.csp.site: 'enforce'`
   ([D-0082](/docs/internal/decisions#D-0082)). The editor sends its own
   [headers](/docs/security-headers#editor).
7. **A shared artifact store for several instances.** Pages live in artifacts, so use a shared
   `ArtifactStore` (S3-style); `artifacts-fs` is per machine.
8. **Outbound HTTP.** List external API origins in `http.allowedOrigins`; never set
   `http.insecureDevOrigins` in production. Bind each secret to its origins.

See the [trust model](/docs/concepts/trust-model) and [security headers](/docs/security-headers).
