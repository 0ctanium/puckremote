A **theme** is a named set of [files](/docs/concepts/artifacts) (its code and templates), like a
theme in a Shopify store
([OnlineStoreTheme](https://shopify.dev/docs/api/admin-graphql/latest/objects/OnlineStoreTheme),
[D-0444](/docs/internal/decisions#D-0444)). Pushing code or saving a template changes its files
(only those that changed), and publishing makes a theme live.

## Roles

| Role | What it is |
|---|---|
| `main` | The live theme: public pages render it. At most one. |
| `unpublished` | A theme in the library, waiting to go live: previewed, customized in the editor, then published. Publishing it makes the previous main theme `unpublished`. |
| `development` | A developer's temporary theme, created by [`puck-remote dev`](/docs/guides/theme-dev): one per device, named after it (`Development (a3f9c1-macbook)`), deleted after `themes.devExpiryDays` days without a push (default 7). |

## One theme or several

By default a site has **a single theme** ([D-0445](/docs/internal/decisions#D-0445)): the first
`puck-remote push` creates the main theme and later pushes update it. There is nothing to
configure, and nothing else exists: other roles, `duplicate`, `publish`, previews and `dev` are
refused (`409 this site has a single theme (themes.multiple is false)`).

To have a theme library like Shopify's, opt in:

```ts title="puck-remote.config.ts"
export default defineConfig({
  // …
  themes: { multiple: true },
});
```

Then developers work on their own development theme (`puck-remote dev`), share work as
unpublished themes (`puck-remote share`, `push --unpublished`), and anyone allowed publishes a
theme when it is ready (`puck-remote publish`, or your admin's theme library).

## Previewing a theme

A non-main theme can be seen on the public site through a signed, expiring
[preview link](/docs/http-api#preview-route); the API returns one for every non-main theme when
`preview` and `origins.site` are configured. In the admin, the editor opens any theme with your own
UI (the example app uses `?theme=<id>`).

## In code

`core.themes` lists and changes themes with the same rules as the API
([D-0456](/docs/internal/decisions#D-0456)):

```ts
const main = await core.themes.main();
const draft = await core.themes.create({ name: 'Summer', role: 'unpublished' }); // no files yet
await core.themes.writeFiles(draft.id, files); // manifest.json + every file (or only changed ones)
await core.themes.publish(draft.id);
```

Refused operations throw `ThemeError` with a `status` (400, 404 or 409). When the main theme's
hash changes, the site switches to it right away ([D-0516](/docs/internal/decisions#D-0516)).
