The repository contains a complete working setup: an example Next.js host, an example theme and a
mock external API. It is the fastest way to see puck-remote running, and the way to use it until
the packages are published.

## Requirements

- **Native arm64 Node 26** on Apple Silicon (`node -p process.arch` → `arm64`), or Node 24+ on
  Linux. `.nvmrc` says `26`.
- **pnpm 12**: `npm i -g pnpm` (Node 26 no longer bundles corepack).

<Steps>
<Step>

### Install and build the packages

```bash
pnpm install
```

```bash
pnpm build
```

Packages ship compiled ESM; `pnpm dev` keeps them rebuilding in watch mode.

</Step>
<Step>

### Publish the example theme

```bash
pnpm --filter theme release
```

This runs `puck-remote build && puck-remote publish` and creates `artifacts/v1` and
`artifacts/current.json`.

</Step>
<Step>

### Start the mock API

```bash
pnpm --filter mock-api start
```

It listens on `http://localhost:4010` and backs the theme's `events` adapter.

</Step>
<Step>

### Start the host

```bash
pnpm --filter host dev
```

| Surface | URL |
|---|---|
| Public site | `http://localhost:3100/` (or `http://site.localhost:3100/`) |
| Search page (uncacheable) | `http://localhost:3100/search?q=nonce` |
| Editor | `http://editor.localhost:3100/editor` |

`*.localhost` resolves to loopback, so the site and the editor are two origins on one app. On the
site hostname, `/editor` and `/api/*` answer 404.

</Step>
<Step>

### Change the theme

Edit a block in `examples/theme/blocks`, then run `pnpm --filter theme release` again. The host
picks up the new version within 2 seconds, with no restart. Roll back with:

```bash
cd examples/theme && ./node_modules/.bin/puck-remote activate 1 --artifacts ../../artifacts
```

</Step>
</Steps>

## What's in the repository

```files
puck-repository-poc
├── packages
│   ├── sdk
│   ├── cli
│   ├── core
│   ├── next
│   ├── artifacts-fs
│   ├── pages-fs
│   └── source-mock
├── apps
│   ├── host
│   └── docs
├── examples
│   └── theme
├── mock
│   └── api-server
├── artifacts
└── data
```

| Path | Content |
|---|---|
| `packages/sdk` | `@puck-remote/sdk`: theme API and host contracts |
| `packages/cli` | `@puck-remote/cli`: build, publish, activate |
| `packages/core` | `@puck-remote/core`: the engine |
| `packages/next` | `@puck-remote/next`: Next.js bindings |
| `packages/artifacts-fs`, `pages-fs`, `source-mock` | File-based and example adapters |
| `apps/host` | Example Next.js app |
| `apps/docs` | This documentation |
| `examples/theme` | Example theme (the "developer repo") |
| `mock/api-server` | External API stand-in |
| `artifacts`, `data` | Published theme versions (git-ignored); pages and seed data |

## Useful commands

| Task | Command |
|---|---|
| Tests | `pnpm test` |
| Typecheck | `pnpm typecheck` |
| Package lint | `pnpm lint:pkg` |
| Benchmarks | `pnpm --filter @puck-remote/core bench` |
| Docs | `pnpm docs:dev` (port 3200) |

In development the editor is open (`devAllowAll()`). A production build refuses to start without
an `auth` adapter; the example uses `sharedSecretAuth` with `PUCK_REMOTE_ADMIN_TOKEN` (see
[Environment](/docs/environment)).
