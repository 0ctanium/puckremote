The repository contains a complete working setup: an example Next.js host, an example theme and a
mock external API. It is the fastest way to see puck-remote running, and the way to use it until
the packages are published.

## Requirements

- **Native arm64 Node 26** on Apple Silicon (`node -p process.arch` → `arm64`), or Node 24+ on
  Linux. `.nvmrc` says `26`.
- **pnpm 12**: `npm i -g pnpm` (Node 26 no longer bundles corepack).

<Steps>
<Step>

### Install and build the packages

```bash
pnpm install
```

```bash
pnpm build
```

Packages ship compiled ESM; `pnpm dev` keeps them rebuilding in watch mode.

</Step>
<Step>

### Publish the example theme

```bash
pnpm --filter theme release
```

This runs `puck-remote build && puck-remote publish` and creates `artifacts/v1` and
`artifacts/current.json`.

</Step>
<Step>

### Start the mock API

```bash
pnpm --filter mock-api start
```

It listens on `http://localhost:4010` and backs the theme's `events` adapter.

</Step>
<Step>

### Start the host and the editor app

```bash
pnpm --filter host dev
```

```bash
pnpm --filter editor dev
```

| What | URL |
|---|---|
| Public site | `http://localhost:3100/` (or `http://site.localhost:3100/`) |
| Search page (uncacheable) | `http://localhost:3100/search?q=nonce` |
| Admin page (editor frame + Publish) | `http://admin.localhost:3100/admin` |
| Editor app (embedded only) | `http://127.0.0.1:3300/` |

`*.localhost` resolves to loopback, so the site and the admin pages are two origins on one app;
the editor app is another site. On the admin hostname, public pages answer 404, and `/admin`
answers 404 elsewhere.

</Step>
<Step>

### Change the theme

Pages edited in the admin page live in the published artifacts. Bring them into the theme first:

```bash
pnpm --filter theme pull
```

Edit a block in `examples/theme/blocks` (and the pages in `examples/theme/pages` that use it), then
run `pnpm --filter theme release` again. The host picks up the new artifact within 2 seconds, with
no restart. Roll back by activating an older artifact id (see `ls artifacts`):

```bash
cd examples/theme && ./node_modules/.bin/puck-remote activate <id> --artifacts ../../artifacts
```

</Step>
</Steps>

## What's in the repository

```files
puck-repository-poc
├── packages
│   ├── sdk
│   ├── cli
│   ├── core
│   ├── next
│   ├── editor
│   ├── artifacts-fs
│   └── source-mock
├── apps
│   ├── host
│   ├── editor
│   └── docs
├── examples
│   └── theme
├── mock
│   └── api-server
├── artifacts
└── data
```

| Path | Content |
|---|---|
| `packages/sdk` | `@puck-remote/sdk`: theme API and host contracts |
| `packages/cli` | `@puck-remote/cli`: build, publish, pull, activate |
| `packages/core` | `@puck-remote/core`: the engine |
| `packages/next` | `@puck-remote/next`: Next.js bindings |
| `packages/editor` | `@puck-remote/editor`: editor protocol, `<PuckEditorFrame>`, iframe bridge |
| `packages/artifacts-fs`, `source-mock` | File-based and example adapters |
| `apps/host` | Example Next.js app (public site + admin page) |
| `apps/editor` | The static editor app |
| `apps/docs` | This documentation |
| `examples/theme` | Example theme (the "developer repo"), with its pages |
| `mock/api-server` | External API stand-in |
| `artifacts`, `data` | Published theme artifacts (git-ignored); CMS seed data |

## Useful commands

| Task | Command |
|---|---|
| Tests | `pnpm test` |
| Typecheck | `pnpm typecheck` |
| Package lint | `pnpm lint:pkg` |
| Benchmarks | `pnpm --filter @puck-remote/core bench` |
| Docs | `pnpm docs:dev` (port 3200) |

Auth belongs to the app. In development the example's admin page and RPC route are open; in
production they require `PUCK_REMOTE_ADMIN_TOKEN` (see [Environment](/docs/environment)).
