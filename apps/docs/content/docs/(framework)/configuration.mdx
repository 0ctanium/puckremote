```ts title="puck-remote.config.ts"
import { defineConfig } from '@puck-remote/core/config';

export default defineConfig({
  artifacts, source, // required adapters
  // everything else is optional
});
```

`defineConfig` is a typed identity function from `@puck-remote/core/config`, which never loads the
sandbox. The proxy and your app can therefore import the config file safely. Defaults are applied
when the engine starts, together with the [checks](#checks).

## Root fields

Every template's root holds the props your app needs around the content, for example the SEO
title and description its routes turn into metadata. Declare them once in `root`
([D-0372](/docs/internal/decisions#D-0372)):

```ts title="puck-remote.config.ts"
export default defineConfig({
  // …
  root: {
    fields: {
      title: { type: 'text', label: 'Page title' },
      description: { type: 'textarea', label: 'Meta description' },
    },
    defaultProps: { title: 'Untitled page', description: '' },
  },
});
```

<TypeTable
  type={{
    'root.fields': { description: "Root fields of every template, with the same JSON shapes as block fields (text, select, array, host:media…). Validated at startup (ConfigError).", type: 'Record<string, FieldSpec>', default: '{}' },
    'root.defaultProps': { description: "Their default values, used for a new template.", type: 'Record<string, unknown>', default: '{}' },
  }}
/>

The editor shows your fields first, then the theme's own root fields. A theme cannot override
yours: on a name collision your field is used and a warning is logged once per theme version
([D-0373](/docs/internal/decisions#D-0373)). The theme's root component receives your props too;
it types them with `Register.rootProps` (see [Root props from the app](/docs/sdk/blocks#root-props-from-the-app)).

## Checks

The engine refuses a config where:

- `origins.host` is empty;
- `origins.editor` is also a host origin;
- `preview.secret` is empty.

There is no `auth` option: the core has no authority of its own. Your app authenticates its admin
pages, RPC handlers and publishing actions with its own session, and the artifacts API with the
`authorize` function it gives `createArtifactsHandler`.
