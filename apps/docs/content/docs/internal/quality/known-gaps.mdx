---
title: Known gaps
description: Accepted limitations and what is planned about them.
---

| Gap | Mitigation / plan |
|---|---|
| isolated-vm is in maintenance mode; a V8 escape runs native code, unchecked by Node's permission model | `bubblewrap()` on Linux (experimental); remote renderer planned for M5 ([D-0075](/docs/internal/decisions#D-0075)) |
| Island HTML is rendered with the theme's React in the isolate and hydrated with the app's React; a version difference or a first render that reads `window`, time or randomness causes a hydration mismatch | React 19 client-renders the island and reports it through `onRecoverableError` ([D-0253](/docs/internal/decisions#D-0253)) |
| Islands can't receive `children` or contain slots; props are JSON only | By design ([D-0248](/docs/internal/decisions#D-0248)) |
| On the admin page, Puck records the data resolved at load (`resolveData`) as undo steps: undoing past the first edit removes the blocks' data (they show "Unavailable" until redo) | Puck's own behavior; a fix (reset the history once the first resolution is done) is not decided |
| Blocks in one request share a context | Accepted ([D-0026](/docs/internal/decisions#D-0026)) |
| Theme client scripts don't run in the editor canvas; `head.*` is ignored there | By design: blocks are real components in the editor ([D-0192](/docs/internal/decisions#D-0192)) |
| Next marks dynamic pages `no-store`; `x-template-cacheable` is only a signal; templates render and run their queries on every request | No caching in the core ([D-0187](/docs/internal/decisions#D-0187)); cache in the data source or the CDN |
| No dependent (`$ref`) queries, no pagination helpers | Post-V1 ([D-0072](/docs/internal/decisions#D-0072)); client-side loading is the theme's job ([D-0011](/docs/internal/decisions#D-0011)) |
| No history UI or concurrent-edit merging in the core | Plugins on `writeTemplate` and themes ([D-0190](/docs/internal/decisions#D-0190)); the example publishes on save and refuses a stale base (`expect`); unpublished themes and previews are built in ([D-0444](/docs/internal/decisions#D-0444)) |
| `publish` from the CLI replaces templates edited since the last `pull` | As in Shopify; run `puck-remote pull` first ([D-0199](/docs/internal/decisions#D-0199)) |
| Every page save stores a full artifact copy (`artifacts-fs` dedupes only identical artifacts) | Accepted for now; a store may share unchanged files internally |
| No template list or delete in the core | Not in scope; an app can list `templates/` entries of the manifest |
| No richtext or inline-editing field types in the SDK yet (the editor now runs real components, so Puck supports them) | M4, mandatory for V1 ([D-0071](/docs/internal/decisions#D-0071)) |
| No localization | Post-V1, app-defined `LocaleResolver` ([D-0073](/docs/internal/decisions#D-0073)) |
| Single tenant | ([D-0009](/docs/internal/decisions#D-0009)) |
| `artifacts-fs` is per machine | Plug a shared store for clusters (e.g. `payloadArtifactStore`) |
| `payloadArtifactStore` stores files as base64 text (about a third larger; 16 MB per file on MongoDB) and polls the theme list (no change feed) | Accepted ([D-0577](/docs/internal/decisions#D-0577), [D-0578](/docs/internal/decisions#D-0578)) |
| Pages running a `requireRequest` source's queries (e.g. Payload) are never cacheable | By design: results may differ per visitor ([D-0596](/docs/internal/decisions#D-0596)) |
| The Payload Local API cannot cancel a running query when the page's data deadline passes | The query is not started when the deadline already passed; its result is dropped |
| `resolveData` stripping is our convention, not enforced by Puck | Tested (test 18) |
| Manifests are not signed; who may publish is only the app's `authorize` | The artifacts API verifies every uploaded file's hash and the file set before storing ([D-0514](/docs/internal/decisions#D-0514)); signed manifests are not decided |
| `puck-remote dev` rebuilds the whole theme on every change (only changed files are sent, [D-0507](/docs/internal/decisions#D-0507)); live reload is a full page reload of previews only (no HMR, no editor reload) | Accepted for now ([D-0546](/docs/internal/decisions#D-0546), [D-0496](/docs/internal/decisions#D-0496)); incremental builds and hot swap are not decided |
| No history of theme versions: a theme holds only its current files | Rollback = push an older checkout of the theme repo ([D-0508](/docs/internal/decisions#D-0508)) |
| During a push, a reader may see some new and some old files of a theme (each file is atomic, the set is not); the main theme's runtime only switches once the hash is set | As in Shopify ([D-0509](/docs/internal/decisions#D-0509)); asset `?v=` mismatches are served `no-cache` |
| Two pushes to the same theme at once are not serialized; files may end up mixed (`expect` only protects `dev` and editor saves) | Not decided; push to a theme from one place at a time |
| Stored files are not re-hashed on load; the store is trusted | [D-0509](/docs/internal/decisions#D-0509); uploads are checked by the artifacts API |
| Pushes to a theme replace templates edited on it in the editor | As in Shopify; `pull -t <theme>` first ([D-0465](/docs/internal/decisions#D-0465)) |
| No theme limit, no rename UI in the example, no theme settings or locking | Out of scope ([D-0469](/docs/internal/decisions#D-0469)) |
| No multi-tenancy (per-tenant themes, isolates, secrets) | Not decided; the secret-to-origin binding already exists |
