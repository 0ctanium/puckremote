---
title: Testing strategy and test map
description: What each test suite proves and where it lives.
---

Tests use vitest 5. `pnpm test` builds the packages first (the worker pool forks the built
`render-worker.js`), then runs every package's suite one at a time. The vitest console is
suppressed; debug with `process.stderr.write`. Sandbox suites run against **both** runtimes
(in-process and worker pool).

| # | Test | Where |
|---|---|---|
| 1–6 | Sandbox: no ambient capabilities; `while(true)`; await and timer loops; OOM then recreate; no cross-request pollution; size caps and thrown errors | `packages/core/test/sandbox.test.ts` |
| 7 | SSRF: private/loopback/link-local literals, DNS to private, rebinding (pinned lookup), redirects, allowlist, size cap | `data.test.ts` |
| 8 | Secrets never in isolate inputs or logs; origin-bound | `data.test.ts` |
| 9 | Dedupe: identical queries → one outbound request | `data.test.ts` |
| 10 | Budget: count, bytes, wall time; tree-order degradation | `data.test.ts` |
| 11 | Editor block data ignores caller-supplied spec/data/query/mode | `data.test.ts` |
| 12 | Drafts only in editor (draft) mode | `data.test.ts` |
| 13 | Data source policy: undeclared names, operators, sort, clamps, projection | `data.test.ts`, types in `examples/theme/type-tests.ts` |
| 14 | Forged slot markers are not swapped | `rendering.test.tsx` |
| 15 | hero → card → latest-posts nested, with data and head effects | `rendering.test.tsx` |
