---
title: Rules
description: The non-negotiable rules for everyone working on the repository, especially AI agents.
---

These rules are mirrored in `CLAUDE.md` at the repository root, which AI agents load
automatically.

## 1. No decision without human approval ([D-0094](/docs/internal/decisions#D-0094))

AI agents never decide on their own. **Every** choice, however minor, is made or validated by a
human through an approved plan:

- architecture, data flow, security trade-offs;
- public API, option and type names, defaults, limits, error messages;
- dependencies and versions, file and package layout;
- test strategy, docs structure, wording of user-facing text.

If a new choice appears during implementation, the agent **stops and asks** (a question, or a new
plan). It does not pick the "obvious" option silently. When the choice is recorded anyway without
approval, it is recorded honestly as `agent-unreviewed` / `needs-review`.

## 2. Record every decision

Every approved choice gets a decision ID with `pnpm adr decision` in the branch's ADR, with the
right provenance. Past decisions are never edited or deleted: a changed decision is a **new**
decision with `--supersedes`. See [decision records](/docs/internal/contributing/decision-records).

## 3. Update the docs in the same change

Code changes under `packages/*/src`, `apps/host`, `examples` or `mock` come with docs changes under
`apps/docs/content`. See [docs conventions](/docs/internal/contributing/docs).

## 4. Look before you work

Search the docs and the decision log before proposing anything: the answer, or a constraint, often
already exists (`pnpm adr search <term>`, the docs search, `/decisions`).

## 5. Humans merge

Agents work on branches. A human reviews and merges. `SKIP_DOCS_CHECK=1` is a human-only escape
hatch ([D-0100](/docs/internal/decisions#D-0100)).
