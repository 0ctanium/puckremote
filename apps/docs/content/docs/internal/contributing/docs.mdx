The site is a Fumadocs app in `apps/docs` ([D-0092](/docs/internal/decisions#D-0092)).

```bash
pnpm docs:dev
```

```bash
pnpm docs:build
```

## Structure: five roots (Layout Tabs)

([D-0107](/docs/internal/decisions#D-0107))

```files
apps/docs/content/docs
├── meta.json
├── (framework)
│   ├── meta.json
│   ├── index.mdx
│   ├── installation.mdx
│   ├── concepts
│   ├── next-js
│   ├── guides
│   └── configuration.mdx
├── core
│   └── adapters
├── cli
├── sdk
└── internal
    ├── architecture
    ├── quality
    ├── contributing
    └── decisions
```

| Root | URL | Audience |
|---|---|---|
| Framework (`(framework)`, a folder group) | `/docs` | Developers installing and using puck-remote; includes `@puck-remote/next` |
| Core | `/docs/core` | Engine API and the **Adapters** section (artifacts, data, renderer) |
| CLI | `/docs/cli` | Theme developers building and publishing |
| SDK | `/docs/sdk` | Theme developers writing blocks; adapter authors (`/host`) |
| Internal | `/docs/internal` | People working on puck-remote: architecture, quality, contributing, decisions |

**Audience rule** ([D-0115](/docs/internal/decisions#D-0115)): Framework, Core, CLI and SDK
explain *how to use*, with short "why" notes and "Deep dive" links. Implementation details,
`<Source>` references, test maps, performance and contributor material live in Internal.

Each folder has a `meta.json` (`title`, `pages` order, `---Separators---`; roots add
`"root": true`, `description` and a Lucide `icon`).

## Decisions

ADRs are read straight from `.claude/` and mounted under `/docs/internal/decisions`
([D-0108](/docs/internal/decisions#D-0108)). `internal/decisions/index.mdx` renders
`<DecisionIndex />` from `adr-index.toml`; link a decision as
`[D-0080](/docs/internal/decisions#D-0080)`.

## Components ([D-0111](/docs/internal/decisions#D-0111))

| Need | Use |
|---|---|
| Options, members, props, flags | `<TypeTable type={{ name: { description, type, default, required } }} />` |
| Directory layouts | A fenced `files` block (tree drawn with `├──`), or `<Files>`/`<Folder>`/`<File>`. No comments in tree lines: describe paths in a table |
| Install commands | A fenced `npm` block: rendered as npm/pnpm/yarn/bun tabs |
| Code | Fenced blocks with `title="file.ts"`; alternatives as consecutive blocks with `tab="…"` |
| Procedures | `<Steps>` with one `<Step>` per `###` heading |
| Diagrams | A fenced `mermaid` block (flowchart, sequence, state, class, ER; rendered on the server by beautiful-mermaid) |
| Navigation | `<Cards>` / `<Card>` on index pages; `<Callout>` for warnings |
| Source references (Internal only) | `<Source path="packages/…" />` |

MDX setup: global remark plugins in `apps/docs/source.config.ts`, components in
`apps/docs/components/mdx.tsx`.

## Writing rules

- Explain **why** with a decision link; keep defaults and limits in sync with the code.
- In MDX prose, put anything with braces or angle brackets in backticks.
- TypeTable values are JS strings: use double-quoted descriptions, avoid unescaped quotes.
- One shell command per `bash` block.
