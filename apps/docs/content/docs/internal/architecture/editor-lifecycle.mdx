---
title: Editor lifecycle
description: From opening the admin page to publishing, step by step.
---

1. **Admin page** (server, your app): checks your session, then `remote.loadEditor(props)`
   (404 outside admin origins) → `core.editorPayload(slug)`: reads the page from the current
   artifact (or an empty page with root defaults), `stripResolved` + `rewriteMissing`, and returns
   the payload: artifact id, manifest, data, absolute `bundleUrl` / `assetBase` on the first admin
   origin, `origins`, `site` ([D-0208](/docs/internal/decisions#D-0208)).
2. **`<PuckEditorFrame>`** (admin page, browser) runs `frameProblem`: it must run on an admin
   origin, and `editorUrl`, `editorOrigin` and `payload.origins.editor` must agree. Only then does
   it render the iframe (`sandbox="allow-scripts allow-same-origin allow-forms allow-popups"`,
   `referrerPolicy="no-referrer"`) and listen for messages through `hostMessageHandler`.
3. **Bridge** (editor page, served by `createEditorHandler` on the editor origin, which injects the
   admin origins as a JSON data block read by `app-main.tsx`): `startEditorBridge` posts `ready` to each allowed parent origin (only
   the real parent receives it), then waits for `init` from `window.parent` on an allowed origin.
   `initProblem` checks it runs on `payload.origins.editor`, that the sender is an admin origin
   and that the theme URLs are on an admin origin.
4. **Theme**: the bridge imports `bundle.browser.js` (its bare imports resolve through the editor's
   import map to the editor's own React and SDK) and calls `buildEditorConfig(manifest, theme,
   deps)`:
   - fields via `mapFields` (`host:*` fields are the editor's own Puck custom fields);
   - `resolveFields` from `visibleIf`, evaluated by `isVisible` (never evaluates strings);
   - `resolveData` → the `resolveData` RPC, result stored in `props.__data` with
     `readOnly.__data` ([D-0028](/docs/internal/decisions#D-0028));
   - `render` → `BrowserBlock`: the theme's `render(props, data, ctx)` inside an error boundary,
     with `SlotContext` providing Puck's slot components to the SDK's `<Slot>`.
5. **Styles**: `ctx.assets.style` URLs under the artifact's `assetBase` are injected into Puck's
   canvas iframe by the `iframe` override. Scripts are not run in the editor; `head.*` is ignored.
   Puck's own Publish button is replaced by nothing: publishing is host UI.
6. **Changes**: Puck's `onChange` is debounced (500 ms) and sent as `change` with the full data;
   the frame validates it and calls `onChange`.
7. **Publish** (host UI, the example's plugin): the admin page sends `{ slug, data, base }` to its
   own RPC route; the handler refuses when the pointer moved since `base`, then
   `core.writePage` (`cleanPage`: zod, `restoreMissing`, `stripResolved`) and
   `artifacts.writePointer(id)`, then reloads the host's artifact.

## resolveData details

- Runs on load/insert, when a prop listed in the manifest's `propRefs` changed, or on `force`.
- Keystrokes (`trigger: 'replace'`) are debounced per block (300 ms); superseded calls give up.
- Failures fall back to `{ ok: false, error: 'loading' }` for each data key.
- On the server, `core.resolveBlockData` parses `{ slug, block, props }` with a non-strict schema
  (anything else is dropped), takes the spec from the manifest and runs it in **draft** mode.
