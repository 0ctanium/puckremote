---
title: Build pipeline (CLI)
description: How puck-remote build turns a theme repo into an artifact.
---

`build({ cwd, outDir })` runs on the developer's machine, which is trusted by the developer but
**not by the host**.

1. **List sources**: `blocks/*.{tsx,ts,jsx,js}` (lowercase slug names), `root.*`, `adapters/*`,
   `config/categories.*`, `pages/**/*.json`.
2. **Metadata build**: esbuild bundles a generated entry importing every definition (platform
   node, ESM), writes it to a temp file and `import`s it **in Node**. React and react-dom are
   resolved from the theme repo (`single-react` plugin) so there is exactly one copy.
3. **Validate and serialize** (`validate.ts`): each definition is deep-copied to JSON, failing
   with a path on functions (other than `render`/`toRequest`/`fromResponse`), class instances,
   Dates, Maps, symbols, `undefined`, non-finite numbers; on unknown field types; on forbidden
   keys; on bad refs; on unknown adapters. `propRefs`, `usesRequestParams` and `slots` are derived.
   Categories are checked and blocks' `category` values merged in.
4. **Isolate bundle**: esbuild bundles a second entry that calls `install({ blocks, root,
   adapters })` from `@puck-remote/sdk/runtime`, as a minified **IIFE** (`platform: 'neutral'`,
   `conditions: ['browser']`, `target: es2022`, `NODE_ENV=production`), with `ISOLATE_SHIMS` as a
   banner. It exposes only `__render`, `__toRequest`, `__fromResponse`.
5. **Browser bundle**: the same definitions as an ESM module (`export default { blocks, root }`,
   `platform: 'browser'`, minified). The `editor-globals` plugin replaces each of
   `BROWSER_EXTERNALS` (`react`, `react/jsx-runtime`, `react-dom`, `react-dom/client`,
   `@puck-remote/sdk`) with a module reading `globalThis.__puckRemoteModules[<specifier>]`, whose
   named exports are enumerated from the theme repo's own copy at build time
   ([D-0229](/docs/internal/decisions#D-0229)): no bare imports remain, and loading the bundle without the
   editor's globals throws. Written as `bundle.browser.js`.
6. **Assets**: `assets/` copied as-is.
7. **Pages** (`validatePage`): each `pages/<slug>.json` must have a valid slug path, parse as JSON,
   have Puck's `{ root, content }` shape, and use only blocks of this theme, slots included
   ([D-0199](/docs/internal/decisions#D-0199)). Written back re-serialized.
8. **Manifest**: sha256 of every file (pages included), `artifactVersion` = package version +
   bundle hash prefix, `sdkMajor: 3` (bumped when migrations were removed and pages joined the
   artifact).

The validation here exists for good error messages; the host's zod schema is the real gate.
