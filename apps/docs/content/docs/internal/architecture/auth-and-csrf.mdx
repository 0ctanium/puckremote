## Flow

On the API, `handleApi` runs, in order ([D-0153](/docs/internal/decisions#D-0153)):

1. CSRF (`checkCsrf`) → **403**.
2. `authenticateRequest`: no adapter (development only, warned at startup) → anonymous and allowed;
   `authenticate(request)` null or exception → **401**. Signed-out callers always get 401, never a
   400 that reveals input validation.
3. The route handler parses its input → **400**.
4. The handler calls `ctx.authorize({ slug })`, i.e. `authorizePrincipal` → `authorize(principal,
   action, resource)`; false or exception → **403**.
5. The handler acts.

If a handler returns anything but a 400 without having called `authorize`, `handleApi` throws
instead of answering: a future route that forgets authorization fails closed
([D-0157](/docs/internal/decisions#D-0157)). `loadEditor` uses `authorizeRequest`, which is steps 2 and 4.

| Entry | Action |
|---|---|
| `loadEditor` | `editor:open` |
| `GET /pages`, `/pages/history`, `/pages/revision`, `POST /blocks/resolve`, `/blocks/render` | `page:read-draft` |
| `POST /pages/save`, `/pages/restore` | `page:write` |
| `POST /pages/publish`, `/pages/unpublish` | `page:publish` |
| `POST /pages/delete` | `page:delete` |
| `POST /artifact/reload` | `artifact:activate` |

Every entry except `/artifact/reload` passes `{ slug }` as the resource. `artifact:publish` is
reserved for the artifact upload API (M3b).

## CSRF (`checkCsrf`)

Runs before auth on every API request:

- safe methods pass;
- `x-puck-remote: 1` is required: browsers can't send a custom header cross-origin without a CORS
  preflight (never granted), and forms can't set it;
- if `Origin` is present, it must be the request's own origin or in `allowedOrigins`;
- if not, `Sec-Fetch-Site` (when present) must be `same-origin` or `none`.

## Built-ins

- `devAllowAll()`: everyone is `{ id: 'dev' }`; throws if `NODE_ENV=production`.
- `sharedSecretAuth({ secret, cookie?, actions? })`: `Authorization: Bearer <secret>` or a cookie
  (`puck_remote_token`), compared in constant time. A missing secret denies everyone.

## Why Request-based

The adapter only sees a standard `Request`, so it works in any framework and with any identity
backend ([D-0056](/docs/internal/decisions#D-0056)). The Next binding rebuilds a `Request` from `headers()` for
server components.
