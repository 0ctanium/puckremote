---
title: HTTP source and SSRF defenses
description: How the host performs outbound HTTP for http() queries and adapters.
---

The host, never the isolate, performs I/O ([D-0030](/docs/internal/decisions#D-0030)). Every hop is checked:

1. **Origin binding**: the URL's origin must equal the declared origin (the block's `http()`
   origin, or the adapter's manifest origin) **and** be in `http.allowedOrigins`.
2. **No credentials in the URL**; the path must be origin-relative (no `//`, no backslash).
3. **https only**, except `http.insecureDevOrigins` (dev/test).
4. **Public addresses only**: IP literals are checked directly; hostnames are resolved and every
   address must be public. Blocked ranges include 0/8, 10/8, 100.64/10, 127/8, 169.254/16,
   172.16/12, 192.168/16, the documentation and benchmarking nets, multicast, reserved, `::1`,
   `fc00::/7`, `fe80::/10`, NAT64 and IPv4-mapped addresses (judged by the embedded IPv4).
5. **Pinned lookup**: undici's `connect.lookup` re-resolves and re-validates at connect time, and
   connects to the validated address. A DNS rebind between check and connect is impossible.
6. **Redirects** are followed manually, at most `maxRedirects` (3), **same origin only**, each
   hop re-validated.
7. **Headers**: `host`, `cookie`, `authorization-proxy`, `connection`, `transfer-encoding`,
   `content-length` are forbidden. `{ $secret }` values are substituted **only** if the secret is
   bound to this origin ([D-0031](/docs/internal/decisions#D-0031)).
8. **Limits**: `timeoutMs` (2 s), `maxResponseBytes` (512 KB, streamed and aborted), JSON only.

Error codes: `blocked`, `secret`, `timeout`, `network`, `http-status`, `too-large`,
`invalid-json`. `outbound` counts real connection attempts (tests assert dedupe with it).
