---
title: Artifact loader
description: How the host loads, verifies, swaps and watches theme versions.
---

`ArtifactLoader` holds the current `{ version, manifest, bundle, runtime }`.

## `loadVersion(N)`

1. Read `manifest.json` from the store; decode as strict UTF-8 and parse JSON.
2. Validate with the host's zod schema (`manifestSchema`).
3. Recompute `propRefs` and `usesRequestParams` from the specs (never trust the CLI).
4. For **every** file listed: read it, compare its sha256 to the manifest; keep `bundle.js`.

Any error → `ArtifactError`.

## `reload({ force? })`

```mermaid
stateDiagram-v2
  [*] --> Serving
  Serving --> Checking: pointer changed
  Checking --> Validating: new version
  Checking --> Serving: same version
  Validating --> Swapping: manifest + hashes OK
  Validating --> Serving: rejected (keep last good)
  Swapping --> Serving: new runtime; old disposed after 30 s
```


Serialized (concurrent calls queue). Reads the pointer; if unchanged, nothing happens. Otherwise
it validates the version, creates a runtime through the renderer factory, swaps it in, and disposes
the previous runtime after **30 s** (`disposeGraceMs`) so in-flight requests finish. **It never
throws**: on failure it logs `REJECTED artifact update, still serving vX` and keeps the last good
version.

## `watch(pollMs)`

Uses the store's `watch` change feed when present (fs: a directory watcher), otherwise polls
`readPointer` every `artifactPollMs` ([D-0058](/docs/internal/decisions#D-0058), [D-0065](/docs/internal/decisions#D-0065)).
Timers are `unref`'d.

## The host

`createHost(config)` wires the loader with `renderer({ version, bundle, limits: config.isolate })`,
subscribes the data source's change feed to `cache.invalidateTags`, and creates the HTTP source.
The renderer is chosen here, not in `config.ts`, so the config entry never imports isolated-vm.
