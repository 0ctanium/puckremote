## Boundaries

| Package | Role | May import |
|---|---|---|
| `@puck-remote/sdk` | Theme API (bundled into the isolate), wire contract, host contracts (`/host`), `registerSharedModules` for pages that load theme bundles (`/browser`) | react, react-dom (peers) |
| `@puck-remote/core` | Framework-agnostic engine; `/island` is the internal `'use client'` island component | `@puck-remote/sdk/host` only from the SDK (`/island` alone may use `@puck-remote/sdk/browser`); no Next, no concrete plugins |
| `@puck-remote/next` | Next.js bindings | `@puck-remote/core`; never isolated-vm, the SDK or plugins |
| `@puck-remote/editor` | `<PuckRemoteEditor>` and `useEditor` (`/react`: the editor frame), `<PuckEditorFrame>`, `.Canvas`, `usePuckEditorFrame`, `stripResolved` and the `host:*` field UIs (`/frame`: the admin page's Puck), the protocol (`/protocol`) | `@puck-remote/sdk`, React, `@puckeditor/core` (all peers), types from `@puck-remote/core` |
| `@puck-remote/source-*`, `artifacts-*` | Trusted host plugins | `@puck-remote/sdk/host` |
| App (`examples/app`) | Wiring, admin page (server actions, publish plugin), editor page | `@puck-remote/next`, `@puck-remote/core`, `@puck-remote/editor/frame` and `/react`; plugins only in `puck-remote.config.ts` |

`no-dev-code.test.ts` enforces this table plus the rule that `bundle.js` only flows to the isolate
compiler.

## Builds ([D-0060](/docs/internal/decisions#D-0060))

- tsdown, ESM + `.d.ts` + sourcemaps, `target: node22`, shared settings in `tsdown.shared.ts`
  (`library(entry, extra)`). Dependencies and peers stay external.
- `@puck-remote/editor`'s `frame.js` and `react.js` get a `'use client'` banner (bundling drops
  module directives).
- The core also builds `render-worker.js`, a dist-only entry the worker pool forks.
- The core builds with `tsconfig.build.json` (src only): its tests import other packages' sources
  (the editor parity test), and a declaration build over the test project would write `.d.ts`
  files into those packages ([D-0242](/docs/internal/decisions#D-0242)).

## The `@puck-remote/source` condition ([D-0062](/docs/internal/decisions#D-0062))

Every export has a `@puck-remote/source` condition pointing at `src/`. The workspace's typecheck
(`customConditions` in `tsconfig.base.json`) and vitest resolve it, so tests run on sources without
a build; apps and published consumers get `dist`.

## Peers

`react`/`react-dom` ^19, `@puckeditor/core` ~0.23 (core), `next` ^16 (next). `isolated-vm` is a
regular dependency of the core (Node ≥ 24).

## Releases

- Changesets with all `@puck-remote/*` packages in one **fixed** group ([D-0063](/docs/internal/decisions#D-0063)):
  `pnpm changeset`, `pnpm version-packages`, `pnpm release`.
- `pnpm lint:pkg`: publint + are-the-types-wrong (ESM-only profile).
- `.github/workflows/release.yml` is manual and needs `NPM_TOKEN`.
- License: MIT ([D-0061](/docs/internal/decisions#D-0061)).

## One runtime per process

`createCore` memoizes on `globalThis` by `config.id` ([D-0047](/docs/internal/decisions#D-0047)), so every Next
route bundle and HMR share one artifact loader and worker pool.
