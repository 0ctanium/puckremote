---
title: Fields
description: Field types, their options and the values they give your render function.
---

Fields are JSON. Each one becomes a prop of the block, with a typed value in `render`.

```ts
fields: {
  heading: { type: 'text', label: 'Heading' },
  count: { type: 'number', min: 1, max: 12 },
  layout: { type: 'select', options: [{ label: 'List', value: 'list' }, { label: 'Grid', value: 'grid' }] },
  columns: { type: 'number', visibleIf: { field: 'layout', eq: 'grid' } },
  items: { type: 'array', arrayFields: { label: { type: 'text' } }, itemSummary: 'label' },
  color: { type: 'host:color' },
  content: { type: 'slot' },
}
```

Any other type fails the build, including Puck's `custom`, `external` and `richtext`, and any
option holding a function. Custom editor UIs are provided by the host (`host:*` fields), so no
theme code runs in the editor.

## `visibleIf`

A small JSON condition language, evaluated by the host:

```ts
{ field: 'layout', eq: 'grid' }
{ field: 'size', in: ['m', 'l'] }
{ field: 'mode', not: 'auto' }
{ and: [{ field: 'layout', eq: 'grid' }, { field: 'count', not: 1 }] }
{ or: [ ... ] }
```

It applies to top-level fields.
