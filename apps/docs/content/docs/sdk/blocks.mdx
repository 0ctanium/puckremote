## `defineBlock(definition)`

One block per file, `blocks/<slug>.tsx`, as the default export. The slug (lowercase letters,
digits, dashes) is the block's type name.

```tsx
import { defineBlock, Slot } from '@puck-remote/sdk';

export default defineBlock({
  label: 'Card',
  category: 'Layout',
  fields: { title: { type: 'text' }, body: { type: 'slot' } },
  defaultProps: { title: 'Card' },
  render: (props, data, ctx) => (
    <article>
      <h3>{props.title}</h3>
      <Slot name="body" />
    </article>
  ),
});
```

Everything except `render` must be plain JSON: it is extracted at build time into the manifest.
Pages ship with the theme, so there are no content migrations: change a block's fields and the
pages that use it together ([Templates and publishing](/docs/guides/publishing)).
`permissions`, `resolveData`, `resolveFields`, `resolvePermissions` and `inline` are rejected:
the host owns those Puck features.

### Rules for `render`

- **Synchronous and pure**: no `fetch`, timers, `async`, state or effects in `render` itself. For
  state and event handlers on the page, use a `"use client"` component inside the block: it is
  hydrated in the browser as an island ([interactive components](/docs/guides/interactive-components)).
  Islands take the reserved `hydrate` prop: `'load'` (default), `'idle'` or `'visible'`.
- **Handle data failures**: each data key is `{ ok: true, data }` or `{ ok: false, error }`.
- Limits: 200 ms of CPU and 64 MB of memory by default. A failing block is hidden on the site
  and shown as an error in the editor; the rest of the page renders.

## `<Slot name />`

Renders the nested blocks of a `slot` field. Each slot can be placed once per render. In the
editor it renders Puck's own slot (drag and drop); on the site, a marker the host swaps for the
server-rendered children.

## `defineRoot(definition)`

The frame around every template, in `root.tsx`. Same options as `defineBlock` without `label` and
`category`. The template's content is `<Slot name="children" />`.

```tsx title="root.tsx"
import { defineRoot, Slot } from '@puck-remote/sdk';

export default defineRoot({
  fields: { theme: { type: 'radio', options: [{ label: 'Light', value: 'light' }, { label: 'Dark', value: 'dark' }] } },
  render: (props) => (
    <main data-theme={props.theme} aria-label={props.title}>
      <Slot name="children" />
    </main>
  ),
});
```

### Root props from the app

The host app adds its own root fields to every template (its `root.fields`, see
[Root fields](/docs/configuration#root-fields)); they come first in the editor and a theme field
with the same name is ignored. `render` receives them with the theme's props. Type them once
with `Register.rootProps` ([D-0369](/docs/internal/decisions#D-0369)):

```ts title="puck-remote-env.d.ts"
declare module '@puck-remote/sdk' {
  interface Register {
    rootProps: { title: string; description: string };
  }
}
```

`RootPropsOf<typeof fields>` turns a fields object into its props type, if the app shares its
field definitions with the theme. Metadata (title, description) is the app's job: it reads root
props from the template it loads, not from the theme
([D-0370](/docs/internal/decisions#D-0370)).

## `defineCategories(categories)`

```ts title="config/categories.ts"
import { defineCategories } from '@puck-remote/sdk';

export default defineCategories({
  content: { title: 'Content', components: ['hero', 'latest-posts'] },
  layout: { title: 'Layout', defaultExpanded: false },
});
```
