---
title: Content migrations
description: Change a block's fields without breaking pages that were saved with the old ones.
---

Pages store each block's props as they were saved. When you rename, remove or retype a field,
bump the block's `version` and give a **migration** that turns old props into new ones. Saved
content is upgraded when it is read; nobody has to re-edit pages.

```tsx title="blocks/quote.tsx"
export default defineBlock({
  label: 'Quote',
  // v2 renamed `author` to `cite`.
  version: 2,
  migrations: {
    2: ({ author, ...props }) => ({ ...props, cite: author }),
  },
  fields: { text: { type: 'textarea' }, cite: { type: 'text' } },
  render: (props) => <blockquote>{props.text} — {props.cite}</blockquote>,
});
```

`defineRoot` takes the same two options.

## How it works

- Every saved item remembers its version in `props.__v` (no `__v` means version 1).
- When a page is **rendered** or **opened in the editor**, items older than the block's `version`
  go through each missing step in order. Migrations run in the sandbox, like `render`.
- The public site migrates on every read and doesn't write anything. The editor shows the migrated
  content, and the next save stores it.
- A migration receives the block's **field values only** and returns new ones. The host keeps the
  item's `id` and its slot content, and ignores any `__` key a migration returns.

Migrations must be pure and synchronous, like `render`. The old props are whatever was saved, so
treat them as untyped.

## When a migration fails

- On the site, that block renders as a failed block (empty) and the rest of the page renders.
- In the editor, the block keeps its old props and the header shows `Migration failed: <blocks>`.
- An item saved by a **newer** theme version (after a rollback) is rendered as is, with a warning in
  the server log.

## Catching a forgotten bump

```bash
puck-remote build --baseline ../previous-dist/manifest.json
```

The build fails when a block's fields changed but its `version` didn't, or when a version went
down. It compares field names, types, nested `arrayFields`/`objectFields` and select/radio option
values; labels and defaults can change freely. Blocks that were added or removed are fine.

`puck-remote publish` runs the same check against the **active** version in the artifact store and
refuses to publish unless you pass `--force` ([D-0147](/docs/internal/decisions#D-0147)).
