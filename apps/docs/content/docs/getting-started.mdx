## Requirements

- **Native arm64 Node 26** on Apple Silicon (`node -p process.arch` must print `arm64`).
  isolated-vm 7.0.1 ships prebuilds for darwin-arm64 but not darwin-x64, so an x64 Node under
  Rosetta fails to load it. `.nvmrc` and `.node-version` say `26`. CI also covers Node 24 on Linux
  x64/arm64.
- **pnpm 12** (`npm i -g pnpm`; Node 26 no longer bundles corepack).
- Every script sets `NODE_OPTIONS=--no-node-snapshot`, which isolated-vm requires on Node ≥ 20.

## Install and build

```bash
pnpm install
pnpm build
```

Packages ship compiled ESM (tsdown), so they must be built before the app or CLI runs. `pnpm dev`
runs `tsdown --watch` for every package plus the host app.

## Run the example

Build and publish the example theme (`examples/theme`) into `artifacts/`:

```bash
pnpm --filter theme release
```

Start the mock external API (port 4010; it backs the `events` adapter):

```bash
pnpm --filter mock-api start
```

Start the host (port 3100, `PORT` overrides it):

```bash
pnpm --filter host dev
```

The site and the editor are **two hostnames on the same app** ([D-0079](/decisions#D-0079),
[D-0090](/decisions#D-0090)); `*.localhost` resolves to loopback:

| Surface | URL |
|---|---|
| Public site | `http://localhost:3100/` or `http://site.localhost:3100/` |
| Search page (uncacheable) | `http://localhost:3100/search?q=nonce` |
| Editor | `http://editor.localhost:3100/editor` |

On the site hostname, `/editor` and `/api/*` answer 404.

In development the editor is open (`devAllowAll()`). A production build refuses to start without
an `auth` adapter; the example app then uses `sharedSecretAuth` with `PUCK_REMOTE_ADMIN_TOKEN`
(see [environment variables](/docs/reference/environment)).

## Publish a new theme version

Edit `examples/theme`, then run `pnpm --filter theme release` again. The host picks up the new
pointer (store change feed, or polling every 2 s), verifies it, and swaps the runtime with no
rebuild or restart. Roll back by moving the pointer:

```bash
cd examples/theme && ./node_modules/.bin/puck-remote activate 1 --artifacts ../../artifacts
```

## Tests, checks and benchmarks

```bash
pnpm test
```

```bash
pnpm typecheck
```

```bash
pnpm lint:pkg
```

```bash
pnpm --filter @puck-remote/core bench
```

The benchmark needs a published artifact and the mock API running.

## Documentation and decisions

```bash
pnpm docs:dev
```

The docs run on `http://localhost:3200`. Decisions are queried from the terminal with `pnpm adr`
(see [Decision records](/docs/contributing/decision-records)).

## Repository layout

```
packages/sdk          @puck-remote/sdk: theme API (bundled into the isolate) + /host contracts
packages/cli          @puck-remote/cli: puck-remote build | publish | activate
packages/core         @puck-remote/core: framework-agnostic engine (no Next imports)
packages/next         @puck-remote/next: Next.js App Router bindings
packages/source-mock  example DataSource (in-memory CMS)
packages/pages-fs     example PageStore (JSON files)
packages/artifacts-fs default ArtifactStore (version dirs + atomic pointer)
apps/host             example Next app (~80 lines of wiring)
apps/docs             this documentation (Fumadocs)
examples/theme        the "developer repo"
mock/api-server       external API stand-in (events, redirects, slow/big responses)
artifacts/            published versions (git-ignored) + current.json
data/                 pages (JSON) and seed data for the mock source
spike/                step 0 spike: isolated-vm + React renderToString
.claude/              decision records (ADRs), index, helper, skills, hooks
```
