## `createCore(config): PuckRemoteCore`

Resolves the config and returns a **process-wide runtime memoized on `globalThis` by
`config.id`**, so every route bundle and dev HMR share one artifact loader, worker pool, cache and
watcher. The first artifact load happens lazily on first use.

| Member | Purpose |
|---|---|
| `config` | The resolved `HostConfig` |
| `host()` | The stateful services (artifact loader, data source, HTTP, cache) |
| `preparePage(slug, query?, context?)` | Resolve data and render every block; `null` for unknown pages or (with `context.request`) a non-site origin |
| `loadEditor(slug, request)` | Editor props; throws `WrongSurfaceError` (404) or `AccessDeniedError` (401/403) |
| `handleApi(request)` | Fetch-style API handler ([HTTP API](/docs/reference/http-api)) |
| `handleTheme(request)` | Fetch-style asset handler (GET/HEAD) |

`PageContext` is `{ locale?, request? }`. `PreparedPage` carries `version`, `manifest`, `slug`,
`data`, `rendered` (id → `{ ok, html, nonce, error? }`), `head` (title, meta, styles, scripts),
`cacheable`, `uncacheableBlocks`, `stats`, and `scriptNonce` when a binding sets it.

## Rendering components

- `<PuckRemotePage page={page} />`: server component. Emits theme stylesheets (React 19 hoisting,
  `precedence="theme"`), Puck's RSC `<Render>`, and theme scripts with the CSP nonce.
- `pageMetadata(page)`: `{ title, description, other }`, compatible with Next's `Metadata`.
- `<EditorClient {...editorProps} />`: the Puck editor (client component).
