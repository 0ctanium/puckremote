---
title: CLI (puck-remote)
description: Build, publish and activate theme artifacts.
---

```
puck-remote build    [--cwd .] [--out dist]
puck-remote publish  [--cwd .] [--out dist] --artifacts <dir>
puck-remote activate <version> --artifacts <dir>
```

| Command | Effect |
|---|---|
| `build` | Writes `dist/manifest.json`, `dist/bundle.js`, `dist/assets/**` ([build pipeline](/docs/internals/build-pipeline)) |
| `publish` | Writes `dist/` as the next version (max existing + 1, never reused) and moves the pointer |
| `activate <N>` | Moves the pointer to an existing version (rollback) |

`--artifacts` defaults to `PUCK_REMOTE_ARTIFACTS_DIR`. A directory means `fsArtifactStore`.
Build errors print `✖ build failed: <file>: <reason>` and exit 1; bad usage exits 2.

## Programmatic API (`@puck-remote/cli`)

```ts
import { build, publish, activate } from '@puck-remote/cli'

await build({ cwd: 'examples/theme', outDir: 'dist', quiet: true })
await publish({ distDir: 'examples/theme/dist', artifacts: myS3Store })   // any ArtifactStore
await activate(myS3Store, 3)
```
