---
title: Integrating into a Next app
description: The handful of files a Next.js App Router app needs to host puck-remote.
---

All logic lives in `@puck-remote/core`; `@puck-remote/next` only adapts Next conventions
([D-0044](/decisions#D-0044), [D-0045](/decisions#D-0045)). The example app is `apps/host`.

## 1. Config: the only file that knows the backend

```ts title="puck-remote.config.ts"
import { defineConfig, devAllowAll, sharedSecretAuth } from '@puck-remote/core/config'
import { fsArtifactStore } from '@puck-remote/artifacts-fs'
import { fsPageStore } from '@puck-remote/pages-fs'
import { mockCms } from '@puck-remote/source-mock'

export default defineConfig({
  artifacts: fsArtifactStore({ dir }),
  source: mockCms({ dataFile }),
  pages: fsPageStore({ dir: pagesDir }),
  auth: process.env.NODE_ENV === 'production' ? sharedSecretAuth({ secret: process.env.PUCK_REMOTE_ADMIN_TOKEN }) : devAllowAll(),
  origins: { site: ['https://www.example.com'], editor: ['https://admin.example.com'] },
  site: { name: 'My site', locale: 'en' },
  http: { allowedOrigins: ['https://api.example.com'] },
  secrets: { EVENTS_API_KEY: { value: process.env.EVENTS_API_KEY!, origins: ['https://api.example.com'] } },
})
```

Resolve data paths from `process.cwd()`: `import.meta.dirname` is undefined in Next server bundles
([D-0048](/decisions#D-0048)). Every option is in the [config reference](/docs/reference/config).

## 2. The app instance

```ts title="src/puck-remote.ts"
import { createPuckRemote } from '@puck-remote/next'
import config from '../puck-remote.config.ts'

export const remote = createPuckRemote(config /*, { loginUrl: '/login' } */)
```

## 3. Proxy

```ts title="src/proxy.ts"
import { createProxy } from '@puck-remote/next/proxy'
import remoteConfig from '../puck-remote.config.ts'

export const proxy = createProxy(remoteConfig)
export const config = { matcher: ['/((?!_next/|favicon\\.ico).*)'] }
```

The matcher must be a literal. The proxy routes surfaces per hostname, sets security headers with
a per-request CSP nonce, and sets cache headers.

## 4. Routes

```tsx title="src/app/[[...path]]/page.tsx"
import { PuckRemotePage, type PageProps } from '@puck-remote/next'
import { remote } from '@/puck-remote.ts'

export const dynamic = 'force-dynamic'
export const generateMetadata = remote.generateMetadata

export default async function Page(props: PageProps) {
  const page = await remote.loadPage(props /*, { locale } */)
  return <PuckRemotePage page={page} />
}
```

```tsx title="src/app/editor/[[...path]]/page.tsx"
import { EditorClient } from '@puck-remote/next'
import { remote } from '@/puck-remote.ts'

export default async function Editor(props: { params: Promise<{ path?: string[] }> }) {
  return <EditorClient {...await remote.loadEditor(props)} />
}
```

```ts title="src/app/api/[[...path]]/route.ts"
export const { GET, POST } = remote.api
```

```ts title="src/app/theme/[[...path]]/route.ts"
export const { GET, HEAD } = remote.theme
```

## 5. Next config

```ts title="next.config.ts"
import { withPuckRemote } from '@puck-remote/next/config'

export default withPuckRemote({ allowedDevOrigins: ['*.localhost'] })
```

`withPuckRemote` keeps `isolated-vm` and `@puck-remote/core` external: the core forks render
workers from its own files ([D-0091](/decisions#D-0091)).

## Other frameworks

Bind to `createCore(config)` from `@puck-remote/core` directly: `preparePage(slug, query, context)`
with `<PuckRemotePage>`, `loadEditor(slug, request)` with `<EditorClient>`, and the fetch-style
`handleApi(request)` / `handleTheme(request)`. Use `@puck-remote/core/edge` in middleware. See the
[core API](/docs/reference/core-api).
