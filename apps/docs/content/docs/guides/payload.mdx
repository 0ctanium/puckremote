<Callout type="warn">Planned for M3. Nothing here is implemented yet, and the details will be decided in the M3 plan.</Callout>

Payload is the first real backend ([D-0054](/decisions#D-0054)). The design constraints already
decided:

- A `@puck-remote/source-payload` **DataSource** translates `NormalizedFind` to the Payload Local
  API with `overrideAccess: false`, a public (or draft-preview) user, and
  `draft: ctx.mode === 'draft'`. It emits `afterChange` hooks through `subscribe` for cache
  invalidation. The core does not change.
- A **PageStore** backed by a Payload collection replaces `pages-fs`. The publishing workflow
  (drafts, publish, history, conflicts, preview links) lives in the PageStore contract
  ([D-0069](/decisions#D-0069)).
- An **AuthAdapter** reads Payload sessions from the standard `Request`
  ([D-0056](/decisions#D-0056)).
- Caching semantics (tags, invalidation events) stay in the core; bindings apply them
  ([D-0070](/decisions#D-0070)).
- Content migrations run in the isolate ([D-0068](/decisions#D-0068)).
